# 园区光纤环网拓扑工作台

园区光纤环网改造前，先找出**单链路断开即隔离站点的薄弱段（图论中的「桥」）**，
再通过试接一条虚拟备纤，独立核对风险是否真正消除。

- React 18 + TypeScript 实现的拓扑工作台
- 迭代式 Tarjan 桥检测，零递归，支持 200 000 站点 / 400 000 链路在 5 秒内完成
- Vitest 以「删边预言机」对随机小多重图逐条核对
- 平行链路、长链、大环均给出精确稳定的结论
- Docker Compose 发布页面，另提供名为 `verify` 的一次性验收服务

## 输入契约

导入内容为普通 JSON 对象，仅使用普通 JSON 基础类型，不含自定义格式：

```json
{
  "sites": ["S1", 1002, "S3"],
  "links": [
    { "id": "L1", "source": "S1", "target": 1002 },
    { "id": "L2", "source": 1002, "target": "S3" }
  ]
}
```

| 规则 | 说明 |
| --- | --- |
| `sites` | 数组，**2 ～ 200 000** 个**唯一、非空**站点编号；元素也可写成 `{ "id": ... }` |
| `links` | 数组，**至多 400 000** 条，链路编号必须唯一 |
| 编号类型 | 非空字符串，或安全整数（`0`、负数均可）；布尔 / `null` / 浮点 / `NaN` / `Infinity` / 对象 / 数组均非法 |
| 端点 | `source`、`target` 必须存在于 `sites`，否则拒绝 |
| 自环 | 禁止 `source === target` |
| 平行链路 | **合法**：同一对端点之间允许任意多条不同编号的链路，它们互为备份 |
| 连通性 | **原图必须连通**，否则拒绝 |
| 多余字段 | 顶层与链路对象中的未知字段将被忽略 |

数字与字符串按转换后的字符串区分（`1` 与 `"1"` 视为同一个编号，重复即拒绝）。

## 基线认证（改造前）

对每条脆弱链路输出一行，**按链路编号的 UTF-8 字节序列做无符号字典序排序**
（ASCII、中文、数字混排结论稳定，不依赖运行环境的 locale）：

- 脆弱链路编号
- 断开后两个连通块中**较小者的站点数**（`min(子树, n − 子树)`）

**不输出站点清单。** 没有脆弱链路时清单为空（全图双连通）。

## 试接备纤（验证消险）

从**现有站点**中选择两个**不同**端点，试接一条虚拟备纤，页面独立显示：

- **仍脆弱**：试接后断开仍会隔离站点的基线脆弱链路；
- **已消除**：相对基线因该备纤而消除风险的链路。

试接是纯虚拟操作：原图对象与基线结果均不被修改、不被重新排序，
可随时回到基线视图复核。备纤本身不出现在清单中（向连通图追加一条边，
该边永远不会成为桥）。

错误处理：

- 非法导入（JSON 语法、契约、连通性等任何一项不满足）——**保留上一次有效拓扑**与基线，仅显示明确中文错误；
- 非法试接（端点不存在、两端点相同、尚未导入）——**保留上一次试接结果**，并显示明确错误。

## 算法说明

- 一条边是桥，当且仅当 DFS 树边 `(p, v)` 满足 `low[v] > tin[p]`；
- **平行边安全**：跳过回边时按「进入当前顶点的那条具体有向弧」精确匹配，
  而非按邻接顶点，因此同端点的多条链路不会被误判为桥；
- 全程使用显式栈（`Int32Array` 栈帧）迭代实现，**无递归调用**，长链不会撑爆浏览器调用栈；
- 前向星定长数组存储，时间复杂度 O(V+E)，上限数据实测亚秒级（测试断言阈值 5 秒）；
- 试接时仅把虚拟边追加到求桥输入，原始拓扑不变，再与基线差集对比。

## 本地开发

```bash
npm install
npm run dev       # 开发服务器
npm test          # 运行 Vitest（删边预言机 + 随机图 + 规模/性能）
npm run build     # 类型检查并产出 dist/
npm run preview   # 本地预览生产构建
```

测试要点：

- `src/core/bridges.test.ts`：手构造图（树 / 环 / 平行边 /双环）、
  300 组随机连通多重图（每组同时核对基线与一次随机试接）、
  删边预言机（朴素 BFS 逐边删除计数）、20 万点长链 / 大环 / 40 万边性能断言；
- `src/core/validation.test.ts`：输入契约全部边界；
- `src/core/workbench.test.ts`：非法导入保留旧拓扑、非法试接保留旧结果、消险差集。

测试使用带种子的伪随机数，结论可复现；**代码中不存在任何固定的分析结果**。

## Docker Compose

```bash
# 发布页面（默认宿主机 8080，可用 WEB_PORT 覆盖）
docker compose up --build -d web
WEB_PORT=9000 docker compose up --build -d web

# 一次性验收：构建并运行全部测试，输出结果后退出，退出码 0 即通过
docker compose --profile verify run --build --rm verify
```

`verify` 是一次性（one-shot）服务：不发布端口、不自动重启，
挂在独立的 `verify` profile 下，不会随 `docker compose up` 启动。

## 目录结构

```
src/
  core/            纯逻辑层（无 DOM，可直接测试）
    ids.ts         编号规范化与 UTF-8 字节序比较
    graph.ts       拓扑数据结构与并查集
    validation.ts  导入解析与契约校验
    bridges.ts     迭代 Tarjan 桥检测（前向星、零递归）
    workbench.ts   导入/试接状态机与结果排序
  ui/              React 工作台（虚拟滚动结果表）
Dockerfile         deps → build → verify / web 多阶段
docker-compose.yml web（WEB_PORT 可覆盖）+ verify（一次性验收）
```
